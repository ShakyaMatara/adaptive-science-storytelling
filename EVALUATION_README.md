# ASCALS Evaluation Harness

Everything in Chapter 7 (Testing) is generated by these commands. Each writes a
timestamped CSV plus a stable `*_latest.csv` into `backend/evaluation/results/`,
so every number in the thesis is traceable to a file and reproducible by re-running
one command.

## Install

Copy these into your repo, preserving paths:

```
backend/evaluation/__init__.py
backend/evaluation/harness.py
backend/evaluation/probes/*.json
backend/core/management/commands/eval_*.py
```

Then:

```
cd backend
.\venv\Scripts\Activate.ps1
pip install matplotlib          # charts only; everything else uses the stdlib
python manage.py eval_probes --verify
```

Add to `.gitignore`: `backend/evaluation/results/`

## Run order

Run in this order. Steps 1–4 cost nothing and should all be done on day one.

| # | Command | Cost | Produces |
|---|---------|------|----------|
| 1 | `eval_probes --suggest --limit 60` | free | Real section headings mined from your index |
| 2 | `eval_probes --verify` | free | Flags any probe your corpus does not support |
| 3 | `eval_gate --sweep` | free | T1: boundary accuracy + threshold calibration |
| 4 | `eval_anticheat --sweep` | free | T2: integrity gate + threshold calibration |
| 5 | `eval_planner` | free | T3: CDIS correlation study |
| 6 | `eval_difficulty --dry-run` then real | ~$0.60 | T5: difficulty ladder validity |
| 7 | `eval_models --dry-run` then real | ~$1.50 | T6: model selection evidence |
| 8 | `eval_faithfulness --dry-run` then real | ~$2.00 | T4: groundedness ablation |
| 9 | `eval_planner --ablate --limit 8` | ~$0.80 | T3b: fixed-length ablation |
| 10 | `eval_charts` | free | All Chapter 7 figures |

Total paid spend ≈ **$5**, leaving headroom in a $10 budget for reruns.

**Always `--dry-run` first** on 6, 7 and 8 — it prints the exact call count without
spending anything. `eval_models` and `eval_faithfulness` also accept `--max-usd` as
a hard stop.

Set `USE_MOCK_LLM=false` in `backend/.env` before steps 6–9. Steps 1–5 work either way.

## Suggested invocations

```powershell
# 1-2  curate the probe sets against YOUR corpus (do this first, it is the input to everything)
python manage.py eval_probes --suggest --limit 60
python manage.py eval_probes --verify

# 3-5  free experiments
python manage.py eval_gate --sweep
python manage.py eval_anticheat --sweep
python manage.py eval_planner

# 6    difficulty ladder
python manage.py eval_difficulty --dry-run
python manage.py eval_difficulty --reps 4 --topics 2

# 7    model benchmark - put 3-4 real OpenRouter ids here
python manage.py eval_models --dry-run --models "a,b,c,d" --prompts 6
python manage.py eval_models --models "a,b,c,d" --prompts 6 --max-usd 2.00

# 8    groundedness ablation
python manage.py eval_faithfulness --dry-run --limit 12
python manage.py eval_faithfulness --limit 12 --judge-model "<a cheap model>" --max-usd 2.50

# 9-10 ablation and figures
python manage.py eval_planner --ablate --limit 8
python manage.py eval_charts
```

## Reporting rules

1. **Report failures.** The lecture notes ask for "even failures and compared to the
   success." Every command prints its misclassifications; put a sample of them in
   the thesis. A result with no failure analysis reads as unexamined.
2. **Never quote a number you cannot point to a CSV for.** If a figure is not in
   `results/`, it does not go in the thesis.
3. **Caption every figure.** APIIT guidance requires a short description of what each
   illustrates; it is a cheap mark to lose.
4. **Validate the LLM judge.** `eval_faithfulness` writes
   `t4_judge_validation_TEMPLATE_latest.csv`. Fill in ~12 rows by hand and report
   your agreement with the judge. Without that, the faithfulness score is an
   assertion; with it, it is a validated instrument.
5. **State the limitations honestly** in 7.x: no classroom deployment, single
   annotator, single corpus, English medium, readability formulae measure surface
   complexity rather than conceptual difficulty.

## Troubleshooting

- `Could not open the Chroma collection` → run `python manage.py build_index`.
- All positives refused in `eval_probes --verify` → your probe wording does not match
  the textbook's. Use `--suggest` and replace them with real headings.
- `eval_models` fails on one model → check the id is live on OpenRouter; the harness
  records the failure and continues rather than aborting the run.
- Judge returns invalid JSON → try a different `--judge-model`; the failures are
  recorded and excluded from the means, and the exclusion should be reported.
